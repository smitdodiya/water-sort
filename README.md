# Water Sort

A water sort puzzle game for Android, built with Expo and React Native.

Pour liquid between glass tubes until every tube holds a single color. Levels are
generated on device from their level number and verified solvable before they are
handed to the player.

## Running it

```bash
npm install
npm start          # then scan the QR code with Expo Go on your phone
```

Everything the game uses is bundled in Expo Go, so no Android SDK or Java
install is needed to play it during development.

## Building an APK

### Locally (no account needed)

The toolchain lives entirely in `~/android-build`, installed without root:

```bash
export JAVA_HOME=~/android-build/jdk
export ANDROID_HOME=~/android-build/sdk
cd android && ./gradlew assembleRelease
```

Output: `android/app/build/outputs/apk/release/app-release.apk`

`android/gradle.properties` builds `armeabi-v7a,arm64-v8a` only. The x86 slices
are for emulators and no phone can use them, so dropping them roughly halves the
NDK compile time. Add them back if you need to run on an emulator.

**The keystore matters.** `android/app/release.keystore` signs the APK. Android
refuses to install an update signed with a different key, so losing it means
users must uninstall before they can update. Back it up.

### Cloud builds

Needs a free Expo account, but no local toolchain:

```bash
npx eas login
npm run build:apk        # eas build -p android --profile preview
```

`eas.json` also carries a `production` profile that produces an app bundle for
the Play Store, and a `development` profile for a custom dev client.

### Regenerating the native project

`android/` is generated by `npx expo prebuild --platform android` and is safe to
delete and regenerate — but doing so **overwrites the signing config**, so
re-apply the `signingConfigs.release` block in `android/app/build.gradle` and
keep `release.keystore` in place.

## Checks

```bash
npm test           # 97 tests over the rules, solver, generator, and store
npm run typecheck  # tsc --noEmit
```

The generator suite is the important one: it sweeps levels 1-30, 31-100,
101-160 and 200-240 and, for every single level, replays the stored solution to
prove the board is genuinely winnable, that each color appears exactly four
times, and that the difficulty lands inside its band.

## How it fits together

```
app/                    screens (expo-router)
  index.tsx             home
  game.tsx              gameplay
  levels.tsx            level select
  settings.tsx
src/
  game/                 pure rules - no React, no React Native
    engine.ts           pour legality, win detection, undo
    solver.ts           DFS solver, also powers hints
    generator.ts        seeded generation, solver-verified
    difficulty.ts       level number -> colors, move band, star thresholds
    rng.ts              mulberry32
  state/                zustand stores, persisted with AsyncStorage
  components/           tubes, liquid, pour stream, confetti, modals
  theme/                palette and responsive board layout
  feedback/             sound and haptics
scripts/                asset generators (see below)
```

`src/game/` deliberately imports nothing from React or React Native. That is
what lets the whole rule set run under plain `ts-jest` in Node, and it keeps the
game logic portable.

### Levels are seeds, not data

A level is generated from its level number with a seeded RNG, then checked with
the solver. If the board is unsolvable, trivially easy, or needs a wildly
unusual number of moves, the seed is bumped and it tries again. So level 47 is
the same board for every player on every device, and no level data is shipped or
stored.

The solver keys its visited set on a *canonical* board string - the tubes are
sorted before hashing, since a board is the same puzzle regardless of which slot
each stack occupies. Collapsing that symmetry is what takes generation from
intractable to milliseconds.

Two empty tubes, always. A single spare tube looks like the obvious difficulty
lever, but a randomly dealt one-empty board is unsolvable the overwhelming
majority of the time. Difficulty rides color count instead, ramping from 3
colors at level 1 to 12 from level 220 on.

### Pours are two-phase

`beginPour` records the move without touching the board, so the tilt-and-stream
animation plays against the state the player can still see. `commitPour` applies
it when the liquid lands, about halfway through. The board is therefore never
out of sync with what is on screen, and input stays locked for the duration.

### Regenerating assets

Sounds and icons are generated from source rather than checked in as opaque
binaries, so they can be retuned by editing numbers:

```bash
npm run gen:sounds   # synthesizes the eight WAV effects
npm run gen:icon     # draws the app icon, splash, and adaptive icon layers
```
